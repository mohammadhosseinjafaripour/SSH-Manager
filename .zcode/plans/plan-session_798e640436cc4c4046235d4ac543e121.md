# SSH Vault — MVP Design & Build Plan

## 1. Platform: Windows desktop app (Electron)

**Not web.** Browsers can't open raw TCP:22 — any web version needs an always-on relay server holding your live SSH sessions and server passwords (worst possible security posture). Desktop keeps every secret local, connects straight to each server, and behaves like PuTTY: double-click → unlock → click → connected.

**Electron over Tauri:** the two hardest parts (SSH engine, terminal emulator) are `ssh2` + `xterm.js` — the most battle-tested libraries in this space; Tauri would mean rewriting both in Rust. Verified current stable: **Electron 45.2.1** (Chromium 156, Node 24). Accepted trade-off: larger binary/RAM than Tauri.

## 2. MVP scope

- One master password gate (first run creates it; forgotten = vault reset — zero-knowledge by design, stated clearly)
- Server list with names, search, tags; add/edit/delete (delete confirms by typing the server name)
- One-click connect → tabbed terminal (xterm), copy-on-select, Ctrl+Shift+V paste
- **Auto-sudo**: per-server toggle + presets (`sudo -s`, `sudo -i`, `sudo su -`, custom); app elevates you to root right after login; sudo password defaults to login password, separate one optional
- PuTTY-style host-key fingerprint pinning (TOFU) with hard-refuse on change
- Auto-lock after idle (default 10 min, configurable), manual lock, dark/light themes
- Windows NSIS installer + portable exe

**v2 backlog (out of scope):** SSH keys/agent, SFTP, port forwarding, snippets, server groups, PuTTY import, sync.

## 3. Screens / UX

1. **Unlock** — centered card, master password with reveal toggle. First-run variant: create + confirm + strength meter + "cannot be recovered" warning.
2. **Servers** — sidebar (All Servers, Tags, + Add Server), top search; rows show name, user@host:port, last connected; hover Edit/Delete; Enter/click connects; empty-state illustration.
3. **Add/Edit modal** — Name*, Host*, Port, Username*, Password* (+ generator), Auto-sudo section, tags, notes, **Test Connection** button.
4. **Terminal** — tab strip (name + status dot + close), xterm fills the window; status pill: connecting / connected / elevated / closed / error; Reconnect button; inline banner on auth failure with "Edit server" shortcut.
5. **Dialogs** — first-seen host key (show fingerprint → accept), host key CHANGED (red; old vs new fingerprints side-by-side; type a confirmation phrase to replace pin), vault problem.

**Keyboard (context-aware — plain Ctrl+L/Ctrl+W must still reach your shell):** inside the terminal app shortcuts use Ctrl+Shift+L (lock), Ctrl+Shift+W (close tab), Ctrl+Shift+F (search), Ctrl+Shift+N (add), Ctrl+Tab (cycle); outside the terminal plain Ctrl+* works.

**Visual:** dark-first near-black neutrals + single teal accent, Inter for UI, JetBrains Mono for terminal, 8pt spacing grid, 150ms transitions, visible focus rings.

## 4. Security architecture

- **Secrets live only in the Electron main process.** Renderer sandboxed (no Node), contextIsolation on, strict CSP, no remote content, no telemetry, single-instance lock, Electron fuses hardened (no runAsNode/inspect, asar-only).
- **Vault:** master password → Argon2id (m=64 MiB, t=3, p=4, 16-byte salt) → AES-256-GCM encrypted JSON at `%LOCALAPPDATA%\SSHVault\vault.bin`; KDF params stored in header for future upgrades; AAD binds header.
- **Durability:** every save = temp file → fsync → rename → rotate previous into `.bak`/`.bak2`, all through a serialized write queue. Unlock failure shows ONE merged message ("wrong password or vault damaged"); backup restore is a deliberate Vault-Tools flow that integrity-checks the backup first (prevents mistyped password → accidental stale-restore data loss).
- **Auto-lock:** terminal input counts as activity; locked screen fully hides terminal content; live SSH sessions keep running; new connections/elevations need re-unlock; key + decrypted payload wiped (best-effort) on lock.
- **Host keys:** pin SHA256 fingerprint per {host, port} (IPv6-safe); mismatch = hard refuse, no "ignore" button; replacement only via side-by-side fingerprint comparison + typed confirmation. Test Connection shows the fingerprint and pins only through the same dialog — never silently.
- **Auth:** ssh2 password auth; if it fails and the server offers keyboard-interactive, auto-answer a single hidden "Password:" prompt with the stored password; anything else (OTP/2FA) → auth modal honoring each prompt's echo flag. Keepalive 15s / 6 missed → session marked disconnected.

## 5. Auto-sudo mechanism (safety invariants)

Over the SSH PTY, when enabled:
1. Send `stty -echo; sudo -S -k -p '[SSHVAULT:<nonce>]' -s; stty echo` — visible command contains no secret; `-k` makes the prompt deterministic; per-attempt random nonce prevents false matches on banners/MOTD.
2. **Invariant: the sudo password is written only after an exact match of the nonce marker — exactly once, never on timeout, never retried, never speculatively.** Echo is off, so the password never appears on screen/scrollback. NOPASSWD servers never prompt → status becomes "elevated (no prompt)" and nothing is sent (this is what prevents the worst leak: password landing in a live shell).
3. No timed writes anywhere: the trailing `; stty echo` restores echo after sudo exits (a timed `stty echo` could be eaten by sudo as a 2nd password attempt → account lockout on slow-LDAP servers).
4. Failure strings ("sorry, try again", "incorrect password attempt", "not in the sudoers file", sudo missing) → error status; **zero automatic retries** (one failure proves the stored secret wrong; retries feed lockout counters).

The elevation detector is a unit-tested state machine (chunk-split markers, missing marker, sudo lecture text, failure strings).

## 6. Data model (inside encrypted payload)

```
Server { id, name, host, port, username, password, authMethod:'password' /*v2 keys*/,
         tags[], notes, elevate{enabled, command, passwordMode:'same'|'custom', customPassword},
         createdAt, updatedAt, lastConnectedAt /*written on disconnect to limit vault churn*/ }
Vault   { version /*header is source of truth*/, servers[], pinnedHostKeys[{host,port}→fp]+history,
          settings{idleLockMinutes, theme} }
```

## 8. Project structure & patterns

```
electron/main/vault    crypto + durable store (repository)
electron/main/ssh      SshSession, ConnectionManager, elevation state machine
electron/main/hostkeys TOFU verifier
electron/main/ipc      typed handlers        electron/preload/bridge.ts
src/features/{unlock,servers,terminal}  components/ stores/ lib/
shared/{types,schemas}  single source of truth for IPC contract
```
Typed IPC contract shared by main + renderer; per-terminal streaming via MessagePorts (no JSON-per-keystroke); renderer never holds secrets beyond the dialog lifetime.

## 9. Build steps

1. Scaffold electron-vite + React 19 + TS strict + Tailwind 4; pin deps; add verify script (typecheck, lint, npm audit, security checklist)
2. Vault: Argon2id + AES-256-GCM, durable store, unit tests (round-trip, tamper, wrong password)
3. Typed IPC + preload bridge + Unlock/first-run screens
4. Servers CRUD, search, add/edit modal, empty states
5. SSH service: connect + auth fallback chain, host-key TOFU, PTY streaming, keepalive, resize
6. Terminal UI: tabs, xterm, status pills, reconnect, copy/paste, context-aware shortcuts
7. Elevation state machine + tests; auto-sudo in modal
8. Auto-lock, settings, themes, Test Connection
9. Package NSIS + portable with fuses; README (threat model, manual update policy); final security pass

## 10. Verification

vitest units (vault round-trip/tamper/wrong-pass, elevation state machine edge cases, host-key verifier, tag normalization) · typecheck + lint · npm audit · Electron fuses/security checklist · manual test matrix vs your real servers (connect, sudo -s and sudo -i, wrong stored password, NOPASSWD server, host-key change, auto-lock, network drop mid-session) · both build targets produce artifacts. Honest limits: no automated e2e in MVP (Playwright next), no code signing (SmartScreen will warn — documented), single local user.

## Assumptions

Your servers run sudo ≥ 1.8 with standard PAM; bash-family shells; Windows 10/11 x64; single user, no sync. "SSH Vault" is a working title — trivially renamed.
